# TECH_DESIGN — ことわり質屋

## 1. 構成【確定】
- **Three.js 0.170.0 + TypeScript 5.8.3 + Vite 6.4.5**。テスト **Vitest 3.2.7**、lint **ESLint 9 + typescript-eslint 8**。依存はすべて完全固定（`package.json` に `^` を付けない）。
- 外部通信なし。絵（ボクセルモデル）・音（WebAudio 合成）はすべてコードで生成。フォントは同梱の DotGothic16（SIL OFL 1.1、`/game/assets/fonts` からコピー）。
- 対応：PC の Chromium 系・Firefox・Safari 最新版（WebGL2 必須）。確認できるのは Chromium（Playwright）だけ。

## 2. 責務の分離【確定】
```
src/core/        描画・DOM に依存しない純粋なロジック（Node のテストで全部動く）
  data/          能力・価格・敵・調整値（数値はここに集約）
  levels/        章ごとの地形・配置データ（箱の集合＋実体）
  physics.ts     AABB の衝突・移動（軸ごとの解決、動く足場）
  player.ts      鈴の状態機械（通常・跳・払・駆・被弾・倒れ）
  enemies.ts     妖の AI（予兆→攻撃→硬直）
  economy.ts     質入れ・請け出し・つけ
  laws.ts        理が世界へ与える効果（浮石の高さ、風、影の足場、時間倍率）
  story.ts       会話・旗・選択
  sim.ts         Sim：固定 60Hz の 1 コマ更新。入力を受けて状態を進め、イベントを出す
  save.ts        セーブ（版つき・移行・破損時の復旧）
  rng.ts         シード乱数
src/render/      Three.js：ボクセル模型、場面の組み立て、低解像度パイプライン、特殊効果
src/audio/       WebAudio：合成音源・BGM の譜面・効果音
src/ui/          DOM の HUD・会話・質屋・メニュー（配置は layout データ 1 か所）
src/input/       キーボード・マウス・ゲームパッド → InputFrame（抽象アクション）
src/app.ts       画面の状態遷移（タイトル・遊び・ポーズ・会話・質屋・結末）
```
- Sim は描画から完全に独立。描画は Sim の状態を読むだけ。イベント（`hit`、`pawn`、`lawChanged` など）で音・演出を起こす。

## 3. 時間と入力【確定】
- 固定タイムステップ 1/60 秒。描画は requestAnimationFrame。溜まった時間を最大 5 コマまで消化（それ以上は捨てて遅延を防ぐ）。
- 入力はキー押下イベントの時点で「押された」を記録し、次の Sim コマで必ず消費する（取りこぼし防止）。`blur`・`visibilitychange` で全キーを離す。
- 先行入力：跳 0.12 秒、払 0.15 秒。コヨーテ時間 0.1 秒。

## 4. 物理【確定】
- 地形は軸平行の箱（AABB）の集合。鈴・妖も AABB。X→Z→Y の順に軸ごとに押し戻す。
- 動く足場（浮石）は前コマとの差分で上に乗る物を運ぶ。
- 空間ハッシュ（2m 格子）で候補を絞る。
- 落下死の判定は高さ `killY`。直前に立っていた安全な足場の位置へ戻す。

## 5. 画作り（3D ドット）【確定（値は仮）】
1. 場面を**低解像度の描画先**へ描く。倍率 `s = max(1, floor(min(W/384, H/216)))`、内部解像度 = `ceil(W/s) × ceil(H/s)`。拡大は CSS の `image-rendering: pixelated` で整数倍（にじまない）。
2. 材質は `MeshToonMaterial`（3 段の陰影、NearestFilter のグラデーション）＋頂点色。ボクセルの面ごとに明度を少し揺らし、手描きの粒感を出す。
3. 月光の平行光は影つき（影マップ 1024、PCF なし＝影の縁もドット）。灯籠は点光源（同時 4 灯まで）。
4. 後処理 1 回：深度の段差で 1px の輪郭（墨色）→ **和の 32 色パレットへ量子化**（4×4 のベイヤー誤差で霧や空の階調）→ 特殊効果。
5. 攻撃予兆・妖の弾・調べられる物はパレット外の「発光色」として量子化から外し、背景より目立たせる。
6. モデルはボクセル（1 粒 = 1/16 m 程度）。部位（頭・胴・腕・脚・扇）ごとに別メッシュで、手続き的に動かす。

## 6. 特殊効果の実装方針【確定（実装は順次）】
すべて内部解像度のバッファ上の全画面シェーダーで、短時間だけ動かす。
| 効果 | 実装 |
|---|---|
| データモッシュ | 前のコマの画を保持し、8px のブロックごとにノイズの「動き」でずらして読み、今の画と混ぜる（I フレームを捨てた P フレームの崩れ方を模す） |
| ドリーズーム | カメラの FOV と距離を同時に変え、注目する物の画面上の大きさを保つ（`dist = h / (2 tan(fov/2))`） |
| タイムスライス | Sim を止め、止まった場面の周りをカメラが半周回る。0.6 秒 |
| ピクセルソート | 明るさのしきい値を超える縦の連なりを、シェーダーで近似的に並べ替える（下方向へ明るさ順に流す） |
| ルーマ・キー遷移 | 次の画面の明るさ < しきい値の画素から先に入れ替わる |
| シネマグラフ | 1 コマを止めて保存し、マスク（灯の火・花びら）の内側だけ生の描画を重ねる |
| コンポーズド・モーフィング | 同じ粒数に並べた 2 つのボクセル模型の粒を補間して移す |
| 3DGS グリッチ | 模型の粒を加算合成の点群にし、粒ごとに位置・大きさを揺らして崩す |
| スカイ・ポータル | 頂点シェーダーで、世界を鈴を中心に上方向へ曲げて折り返す |
| ルマ・フェード・アシッド | 明るさで色相を回しながら暗転 |
| テクスチャフラッシュ | 数コマだけ模型の色を別の模様（パレットの帯）に差し替える。点滅軽減で無効 |

## 7. 音【確定】
- WebAudio で合成：箏（カープラス・ストロング）、尺八（ノイズ＋正弦波＋ビブラート）、太鼓（ピッチの落ちる正弦＋ノイズ）、鈴（金属的な FM）。
- BGM は都節音階の譜面を章ごとに持ち、先読みでスケジュール（ループの継ぎ目が出ない）。音量：BGM・効果音・全体を別々に。最大値はテストで書き出して確認。

## 8. セーブ【確定】
- `localStorage`：`kotowari.save.v1`（進行）と `kotowari.settings`（設定）を分ける。
- 形式 `{ version, chapter, shrine, zeni, debt, pawned[], flags{}, collected[] }`。読み込み時に `migrate()` で補完。JSON 破損は `.bak` から戻し、両方壊れていれば新規。保存できない環境（例外）でも続行する。

## 9. テスト【確定】
- `tests/*.test.ts`（Vitest, Node）：物理・操作感（コヨーテ・先行入力）・経済（無限資源化しない・誤課金しない・つけ）・理の効果・各章の到達可能性（全状態の探索）・物語の旗・セーブ移行・**通しボット（序章から結末まで、複数シード）**。
- `tools/e2e/*.mjs`（Playwright + 同梱の Chromium）：起動、スクリーンショット（複数画面サイズ）、真っ黒検査、UI のはみ出し検査、性能（中央値・最悪のコマ時間）。
- CI：`.github/workflows/kotowari.yml` で型検査・lint・テスト・ビルド。
